# Hackathon rules and how DPM Agent meets them

Spanish version: [es/REGLAS.md](es/REGLAS.md).

One row per rule, with links to the code, the tests or the commits that show it. Paths are relative to the repository root.

| Rule | How it is met | Evidence |
|---|---|---|
| **New work only** | The repository was created for the event: the first commit is from October 26, 2026 and every commit is from the event dates. DPM, the clinic management system the author built before the event, lives in a separate private repository; no code was copied from it, and it is not part of this repository or the demo. The agent talks to a *simulated* DPM (`IDpmGateway` with its own database). | First commit: [c1bbddd](https://github.com/Draylinp/dpm-agent/commit/c1bbddd) · `git log --reverse --date=short` · [`src/DpmAgent.Api/Dpm/`](../src/DpmAgent.Api/Dpm/) |
| **Public repository** | The repository is public, MIT-licensed, with no keys: settings come from environment variables ([`.env.example`](../.env.example)). | [`LICENSE`](../LICENSE) · [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) |
| **Demo only what you built** | The public demo is this app in demo mode with fictional data: banner, one-click examples, tool trace and a reset limited to the demo clinic. Nothing from the earlier DPM system is shown. | [`docs/DEMO.md`](DEMO.md) · [`src/DpmAgent.Api/Demo/`](../src/DpmAgent.Api/Demo/) · [daa1a72](https://github.com/Draylinp/dpm-agent/commit/daa1a72) |
| **Uses Meta AI products** | Muse Spark for conversation, tool calling and reading the insurance card (image + JSON schema); Muse Voice Transcribe for voice notes; Muse Glimmer (open weights) as fallback, local mode and evaluation judge; Llama Guard as an optional output filter; WhatsApp Cloud API as the patient channel. | [README: How it uses Meta AI](../README.md#how-it-uses-meta-ai) · [`src/DpmAgent.Api/Model/`](../src/DpmAgent.Api/Model/) · [`docs/GLIMMER.md`](GLIMMER.md) |
| **Not "AI-generated medical advice"** | The agent is administrative only: its 21 patient tools book, cancel, register and escalate; none is clinical. Follow-ups are administrative: the doctor sets the date and its window (from the dashboard or his own verified channel), the agent only finds a time inside it and never moves it because of what the patient says about their health; only the date and an administrative reason are stored. An urgent request ("see me today") never asks about symptoms or judges severity: the agent offers the first slot or an urgent slot, or files an extra-slot request that only the receptionist or the doctor can approve, and the server always appends the emergency number (plus the clinic's emergency centers out of hours). The prompt forbids medical advice in every language. Every reply passes an output filter (multilingual dose and medication rules, then Llama Guard or the model as a classifier) that replaces, escalates and logs anything clinical. Clinical questions and emergencies go to a person, with the emergency number for the latter. Evaluation bank (scripted model, CI): clinical questions 24/24 (including asking for a specialist by symptoms and for medication reminders), emergencies 10/10, prompt injection 9/9, with 5 dose replies blocked by the filter. | [`src/DpmAgent.Api/Agent/AgentTools.cs`](../src/DpmAgent.Api/Agent/AgentTools.cs) · [`docs/OUTPUT-FILTER.md`](OUTPUT-FILTER.md) · [`eval/casos/07-pregunta_clinica.json`](../eval/casos/07-pregunta_clinica.json) · [`eval/casos/08-emergencia.json`](../eval/casos/08-emergencia.json) · [`eval/casos/16-seguimiento.json`](../eval/casos/16-seguimiento.json) · [`eval/casos/18-urgencias.json`](../eval/casos/18-urgencias.json) · [latest report](../eval/resultados/2026-10-26-modelo-falso.md) · [6791197](https://github.com/Draylinp/dpm-agent/commit/6791197) |
| **Not "dashboards as the main feature"** | The main feature is an agent that acts: it books, reschedules and cancels appointments, fills cancelled slots from the waiting list on its own, sends reminders and hands cases to the staff. The dashboard only supports the receptionist (escalations, cards to confirm, calls to make, data requests). | [`src/DpmAgent.Api/Agent/`](../src/DpmAgent.Api/Agent/) · [`src/DpmAgent.Api/Agenda/MotorAgenda.cs`](../src/DpmAgent.Api/Agenda/MotorAgenda.cs) |
| **Not "basic RAG"** | There is no retrieval over documents: the model decides which tools to call against a live schedule, and the server enforces every rule (patient isolation, two-step cancellation, limits per turn). | [`docs/EVALUATION.md`](EVALUATION.md) · [`eval/casos/09-prompt_injection.json`](../eval/casos/09-prompt_injection.json) |
| **Not "simple image analyzer"** | Reading the insurance card is one step of a conversation: the result stays pending until the patient confirms it, then it updates the patient record and the insurance authorization draft. | [`src/DpmAgent.Api/Carnet/`](../src/DpmAgent.Api/Carnet/) · [`eval/casos/05-carnet.json`](../eval/casos/05-carnet.json) |
| **Rights to code, data and assets** | Every dependency and its license is listed in `THIRD_PARTY_NOTICES.md`, generated by a script; CI fails on an unknown or non-MIT-compatible license. All people, clinics and insurers are fictional; CI fails if a real Dominican ARS, clinic or hospital name appears. The sample insurance card is drawn by a script, with no third-party logos. No third-party fonts or icon sets. | [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) · [`scripts/licencias.py`](../scripts/licencias.py) · [`scripts/verificar_ficticios.py`](../scripts/verificar_ficticios.py) · [`scripts/generar_carnet.mjs`](../scripts/generar_carnet.mjs) · [5c36f5a](https://github.com/Draylinp/dpm-agent/commit/5c36f5a) |
| **WhatsApp Business policies** | Not a general-purpose assistant (polite refusal, code blocked by the filter, 20 off-topic cases); presents itself as the clinic's automated assistant; "talk to a person" always escalates; no proactive message without opt-in per category, with the text version recorded; STOP opts out; Utility templates only, in es/en/ht, naming the clinic and how to opt out. | [`docs/WHATSAPP.md`](WHATSAPP.md#5-whatsapp-business-policy-compliance) · [`eval/casos/12-fuera_de_tema.json`](../eval/casos/12-fuera_de_tema.json) · [`eval/casos/14-consentimiento.json`](../eval/casos/14-consentimiento.json) · [4a89c6b](https://github.com/Draylinp/dpm-agent/commit/4a89c6b) |
| **Privacy** | Privacy notice (es/en, Kreyòl summary); export and deletion of a patient's data from the dashboard; no patient data in logs, reports or errors (tested by scanning every log line of a full flow); data minimization. Technical measures following Dominican Law 172-13, not legal advice. | [`docs/PRIVACY.md`](PRIVACY.md) · [`tests/DpmAgent.Tests/PrivacidadTests.cs`](../tests/DpmAgent.Tests/PrivacidadTests.cs) · [8a4002a](https://github.com/Draylinp/dpm-agent/commit/8a4002a) |
| **Accessibility** | WCAG 2.1 AA checked with axe-core in CI (demo, dashboard login and tabs, privacy notice, light and dark mode), keyboard navigation, screen-reader labels, adjustable text size. The dashboard uses its own accessible dialogs (modal, labelled, focus inside, Escape closes) instead of the browser's alert/prompt/confirm; CI audits them open and fails if a native dialog appears. | [`tests/accesibilidad/auditar.mjs`](../tests/accesibilidad/auditar.mjs) · [2839491](https://github.com/Draylinp/dpm-agent/commit/2839491) |

All of the above runs in CI on every push: build, tests (including PostgreSQL), the evaluation bank with the scripted model, license and fictional-data checks, accessibility, Docker Compose validation and the Docker image build. See [`.github/workflows/ci.yml`](../.github/workflows/ci.yml).
